A friendly, no-jargon guide

Try the Risk Monitor yourself

This walks you through setting up a small project on your own computer, then clicking around a test page to see it work — no coding experience needed, just copying and pasting.

⏱️ about 20 minutes

What is this thing, really? Imagine a robot helper (an "AI agent") that can read files, browse the web, and run commands for you. Handy! But what if it accidentally opens a file full of passwords, or downloads something it shouldn't?

This project is like a security camera for robot helpers. Every time the robot does something, it gets written down. A little detective checks each thing that got written down, and if something looks risky — reading a password file, running a sketchy download — it raises a flag.

By the end of this guide, you'll have that whole system running on your computer, and a simple test page where you can pretend to be the robot and watch the flags get raised in real time.

1

Get three free tools installed

These are just programs your computer needs so it can run the project — like needing a DVD player before you can watch a DVD. If you already have these, skip to Step 2.

🐳 Docker DesktopRuns the project's filing cabinet (its database) in a little sealed box, so you don't have to install one yourself. Get it
🟢 Node.jsLets your computer run the main program (the part that receives and stores everything the robot does). Get it
🐍 PythonLets your computer run the detective (the part that checks for risky behavior). Get it
Tip: install with all the default options — you won't need to change anything during setup. After installing Docker Desktop, open it once and leave it running in the background; everything else in this guide happens in a plain black window called a terminal (on Windows, search for "PowerShell" in the Start menu).
2

Download the project

This copies all the project's files onto your computer, into a folder.

Open a terminal, go somewhere you like (e.g. your Desktop), and run:
git clone https://github.com/Wolve080/kybershield-agent-risk-monitor.git
cd kybershield-agent-risk-monitor
No git? That's fine — go to the project's page, click the green Code button, choose Download ZIP, then unzip it and open a terminal inside that unzipped folder.
3

Give it its secret settings

The project needs a few settings to work — like which password to accept, and where its filing cabinet lives. These live in one file so they're never accidentally shared or uploaded anywhere.

Create a new file named exactly .env in the project folder, and paste this into it:
DATABASE_URL=postgres://kybershield:localdev@localhost:5433/kybershield
PORT=3000
LOG_LEVEL=info
API_KEYS=fleet-1:dev-key-please-change
MAX_BODY_BYTES=524288
ALLOWED_DOMAINS=api.github.com,api.openai.com,registry.npmjs.org
SENSITIVE_READ_THRESHOLD=3
SENSITIVE_READ_WINDOW_SECONDS=300
ANALYZER_BATCH_SIZE=100
ANALYZER_POLL_SECONDS=5
What's a "password" doing in plain text? dev-key-please-change is just a made-up test password for playing around on your own computer — it's not connected to anything real, so there's nothing to protect here.
4

Turn on the filing cabinet

This starts the database — the place everything gets written down. It runs quietly in the background.

docker compose up -d

The first time, this downloads a small program — give it a minute. You'll know it worked if the terminal gives you back control without any red error text.

5

Wake up the security guard

This is the main program — it's the one that will listen for things the robot does and write them down.

1. Install what it needs, and set up the filing cabinet's folders:
npm install
npm run migrate
2. Start it up — and leave this window open the whole time:
npm run dev
How do I know it worked? You'll see a line ending in "listening on 3000". That's it saying "I'm awake and ready." Minimize this window, but don't close it.
6

Wake up the detective

This is the part that actually looks at what got written down and decides if anything looks risky. It needs its own new terminal window — leave Step 5's window running and open a fresh one.

1. In the new window, go back into the project folder, then set it up (only needed once):
cd kybershield-agent-risk-monitor
python -m venv .venv
.venv\Scripts\pip install -r analyzer\requirements.txt
On a Mac or Linux computer, the last two lines are: python3 -m venv .venv then .venv/bin/pip install -r analyzer/requirements.txt
2. Start it — and leave this window open too:
.venv\Scripts\python -m analyzer.main
Mac/Linux: .venv/bin/python -m analyzer.main. It won't print much at first — that's normal, it's just watching quietly.
7

Open the control panel

This is a simple page in your web browser for pretending to be the robot, so you can watch the whole system react.

risk-monitor-tester.html lives at the root of this repo. Just double-click it (or open it in a browser). It'll open straight away. (It's just a page on your own computer; nothing gets sent anywhere except to the program you started in Step 5.)
8

Play with it

Here's what everything on the control panel means:

Base URL / API key
Already filled in correctly — this is how the control panel talks to the security guard from Step 5. Leave these as they are.
Check /health
Click this first. A green pill means everything's connected. Red means one of your two windows from Steps 5–6 isn't running.
Post an event
This is you pretending to be the robot. Pick file_read from the dropdown, click Fill risky example (it'll load up a "read a password file" payload — a classic risky move), and click Send event.
Alerts
Wait about 10 seconds (the detective checks every few seconds), then click Fetch alerts. You should see a new row appear — that's the flag being raised, in real time.
Agent summary / timeline
Type agent-tester into the agent_id box and click fetch — these show a report card and a full history for one "robot," combining everything it did with everything that got flagged.

When you're done

Go to each terminal window from Steps 5 and 6 and press Ctrl + C. Then, to turn off the filing cabinet too:

docker compose down

If something goes wrong

The control panel's health check is red.
One of your two black windows (Step 5 or 6) probably got closed. Reopen a terminal, go back into the project folder, and run its start command again.
"docker compose up" gives an error.
Make sure the Docker Desktop app is actually open and running (look for its icon in your system tray/menu bar) before running that command.
Nothing shows up under Alerts.
Give it a few more seconds and click Fetch alerts again — the detective checks on a short delay, not instantly.
I closed everything and want to start again tomorrow.
You only need to repeat Steps 4, 5's second command, 6's second command, and 7 — the install parts (Steps 1–3, and the first commands in 5 and 6) only ever need doing once.

That's it!

You just ran a real event-monitoring pipeline end to end — stored an action, had it automatically risk-scored, and watched the result. Nothing to break, nothing saved anywhere but your own computer.
